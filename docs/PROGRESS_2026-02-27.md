## Architecture

### Dual-Mode Server
- **stdio mode**: MCP for Claude Desktop / any MCP client (`python -m speech_mcp.server`)
- **webapp mode**: FastAPI on port 10760 + React frontend on port 10761 (`python -m speech_mcp.webapp`)

Both modes share the same `FastMCP` instance and tool definitions. Clean architecture.

### REST API Endpoints (webapp mode)
- `GET /api/v1/health` - provider status + RAG source list + timer count
- `GET /api/v1/search?q=` - semantic search passthrough
- `GET /api/v1/voices` - provider listing
- `WebSocket /ws/stream` - audio stream proxy (currently echo-only)

### RAG Stack
- **LanceDB** for vector storage (`data/lancedb/speech_docs.lance`)
- **FastEmbed** with `BAAI/bge-small-en-v1.5` for embeddings
- `BaseVectorStore` -> `DocumentStore` inheritance pattern, clean
- `search_docs` + `ask_docs` tools expose it to MCP clients
- REST `/api/v1/search` exposes it to the webapp
- Docs in `data/docs/` are the indexable source; `scripts/reindex_docs.py` handles reindexing

### TTS Providers
- **Hume AI** (EVI 2/3 + Octave): primary expressive TTS, real-time sessions
- **ElevenLabs**: voice cloning (PVC), multilingual TTS
- **pyttsx3**: Windows local fallback, no API key needed
- Provider selection via `provider` param in `text_to_speech`

## Issues Found

### Hard Issues

1. **WebSocket stream is echo-only** - `text_to_speech` returns a WebSocket URL but the WS endpoint just echos bytes. No actual Hume/ElevenLabs audio comes through it. This is the core gap between the tool promise and reality.

2. **3 tools missing from working tree** - `detect_wake_word`, `orchestrate_alexa_pattern`, `agentic_conversation_workflow` are in git history (commit `3c861f1`) but not in the current `server.py`. Needs a deliberate merge decision.

3. **`ctx.sample()` signature mismatch in diverged tools** - The agentic expansion tools call `ctx.sample(prompt=..., max_tokens=...)` but FastMCP 3.x takes `messages=` (not `prompt`). Will fail at runtime. The working `ask_docs` tool uses the correct `messages=` form.

### Medium Issues

4. **glama.json version drift** - says `0.2.0`, pyproject says `0.2.1`.

5. **llms-full.txt has duplicate content** - the agentic orchestration guide is pasted twice inside it.

6. **MANIFEST.md factual error** - claims "Antigravity IDE is the only orchestrator capable of closing cognitive loops." This is false - Claude Desktop and Cursor both work fine.

7. **`manage_voice_clones` not in glama.json tool list** - it's a real tool in the server but absent from the registry manifest.

8. **`requires-python` inconsistency** - pyproject.toml says `>=3.11` but llms-full.txt says `python>=3.10`.

### Minor Issues

9. **Backup files in repo** - `server.py.bak`, `rag_core.py.bak`, `pyproject.toml.bak` etc. should be in `.gitignore` or deleted.

10. **CHANGELOG not updated** - v0.2.1 has no entry. v0.2.0 entry says alpha but git tag says beta.

11. **Weather stub** - hardcoded "Wear a reductionist coat." means weather queries silently return fake data with no warning to the caller.
